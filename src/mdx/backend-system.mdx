# 后端体系

## 定位

后端提供中后台基础能力：账号、角色、菜单、部门、权限、日志、上传与认证。

Mock 适合前端联调；进入真实业务后需要可落地的数据与安全边界。

## 技术栈迁移

后端已迁移至 NestJS，并尽量保留原有接口路径与响应结构，降低前端改动成本。

统一响应：

```ts
{
  code: number
  data: unknown
  msg: string
}
```

## 模块划分

- `auth`：登录、退出、Token、会话
- `captcha`：验证码
- `user`：账号
- `role`：角色
- `menu`：菜单与动态路由数据
- `department`：部门
- `log`：操作日志
- `upload`：文件上传
- `prisma`：数据库访问
- `redis`：缓存与验证码临时数据

## 数据层

使用 Prisma，数据库以 MySQL 为主。模型定义集中，类型反馈直接。

本地可用迁移，也可用 `db:push` 快速同步。进入协作后应保留迁移记录。

## 认证与权限

认证使用 JWT，配合 RSA 密钥。安装后可生成本地密钥，部署时可换成固定密钥。

权限由角色、菜单与权限点组合：前端按菜单渲染页面，后端按角色校验接口。

前端隐藏入口只影响体验；后端鉴权是底线。

## Redis

当前主要用于验证码等短期数据。后续会话、限流、缓存可沿用同一思路。

## 本地开发

- 默认端口：`8000`
- 依赖：MySQL、Redis
- 流程：Prisma 初始化 → 种子数据 → 启动服务

默认账号：`Mason / 123456`、`Coder / 123456`，用于联调不同角色菜单与权限。
