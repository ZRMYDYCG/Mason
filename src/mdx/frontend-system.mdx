# 前端体系

## 范围

前端侧负责把中后台高频能力整理成稳定结构：路由、权限、状态、组件、主题与布局。

重点不在单页复杂度，而在页面持续增加时仍能保持一致的组织方式。

## 技术选型

主要技术栈：Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus。

- Vue 3：响应式与组合式 API
- TypeScript：约束接口与数据结构
- Vite：开发与构建
- Element Plus：后台基础控件

不引入不必要的架构概念；需要成文的规则再单独沉淀。

## 目录分层

- `api`：接口请求与类型
- `components`：跨页面通用组件
- `hooks`：组合式逻辑（表格、主题、图表等）
- `Layout`：框架、菜单、顶栏、标签页、主题配置
- `router`：静态路由、动态路由、守卫
- `store`：全局状态
- `views`：业务页面
- `styles`：设计变量与通用样式

目录即约定，用于降低协作成本。

## 页面开发

业务页面只描述业务：筛选、列配置、接口与操作。分页、查询、加载态、表格高度等交给 `useTable` 或通用表格组件。

同类型列表页应保持交互与错误处理一致。

## 组件沉淀

出现稳定、可复用的形态后再抽组件，并写清边界与对外接口。

现有通用能力包括：表格、图标、Toast、Loading、水印、Lottie、错误页等。组件文档会补充使用场景与注意点。

## 状态与权限

Pinia 管理用户、菜单权限、系统设置及跨页面状态。

权限与路由、菜单同源：登录后按菜单动态注册路由，并在入口与按钮层做控制。数据安全仍由后端鉴权保证。

## 样式与主题

亮色 / 暗色、主题色与组件状态统一走 token。后台页面优先清晰与可读，避免抢业务内容注意力。

新增页面优先复用现有变量与布局，不要为单页另起视觉规则。

## 维护检查清单

新增功能时确认：

1. 归属：页面 / 组件 / Hook / Store / Layout
2. 是否会复用
3. 改动会影响哪些已有页面
